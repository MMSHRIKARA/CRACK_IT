Garbage Collection:
==================
=>: Garbage Collection is the process of removing un-used/un-referenced objects from the JVM's Heap area.
=>: Garbage Collection is an in-built process of JVM.
=>: In JVM, Garbage Collector is available to perform Garbage Collection.
=>: Garbage Collector is a daemon thread(runs in background).


	EX:
	===

	package in.ashokit;
	public class Student {

	public static void main(String[] args) {

	// Object created
	Student s1 = new Student();

	// nullifying ( making obj eligible for GC)
	s1 = null;

	System.gc();
	
    }

	protected void finalize() throws Throwable {
	System.out.println("Finalize method called...");
      }
}



=>: When we assign s1= null then s1 become un-referenced object and it is eligible for GC.
=>: When GC identified un-referenced objects then it will call finalize() method and it will remove that object from HEAP Area(memory clean up).



How to invoke GC in java:
==========================
=> In java we have 2ways to invoke GC.

	1.System.gc();
	2.Runtime.getRuntime.gc();

Note: Even if we call above methods there is  no guarantee that JVM will start GC immediately. GC execution process will be managed by JVM only.
=====



How Garbage Collection works internally in JVM :
================================================
=>: Garbage Collection works in below phases

	1.Stop the World: When GC starts it will trigger STOP THE WORLD (All running threads will be stopped for few milli seconds).

	2.Marking: GC will go to JVM Heap Area and it will identify un-referenced objects and it will mark them.

	3.Sweeping: GC will sweep marked objects.

	4.Compaction: After sweeping completed memory holes will be created in Heap Area to clear that GC will perform Compaction(adjusting memory holes). 			 After compaction, GC will give signal to JVM to continue the execution.

Stream API:
===========

=>: Stream API is used to process the data.
Note: COllections are used to store the data.
=>: Stream API is one of the major feature added in java 1.8v
=>: Stream in java can be defined as sequence of elements that comes from a source.
=>: Source of data for the Stream can be array or collection.




Few Important Points about Streams:
===================================

=>: Stream is not a data structure.Stream means bunch of operations applied on source data.Source can be collection or array.
=>: Stream will not change original data structure of the source(It will just process the data given by the source).



Stream Creation:
================

=>:In java we can create Stream in 2ways.

	1.Stream.of(e1,e2,e3......)
	2.stream() method




Stream Operations:
==================
=>: Stream API provoided several methods to perform operations on the data.
=>: We can divide Stream API methods into 2 types.

	1.Intermediate Operational methods:Intermediate operational methods will perform operations on the stream and returns a new stream.
	====================================

=>: It is also called as Non-Terminal Operations or Processing Operations.

					Ex: filter(), map(), flatMap(), distinct(), limit(), sorted(), peek(), skip()

	2.Terminal Operational Methods:Terminal Operational Methods will take input and provide result as output.
	===============================
					Ex: count(), collect(), forEach(), min(), max(), reduce(), toArray() findFirst(), findAny()


Note: After applying non-terminal operations we can apply terminal operations.

	EX: name.stream().flatMap(x->x.stream()).forEach(System.out::println);

	EX: get only even numbers from the given numbers.

Monolithic-Architechture:
========================
Monolithic applications are single-tiered, which means multiple components are combined into one large application. Consequently, they tend to have large codebases, which can be cumbersome(clumsy or gajibiji) to manage over time.
 
-> if one program component must be updated, other elements may also require rewriting, and the whole application has to be recompiled and tested. 

Disadvantages:-
-------------
1. Large and complex applications may tend to have "large code bases"
2. Slow development
3. difficult to understand and modify
4. difficult to adapt new framework
----------------------------------------------------------------------------------------------------------------------------------------

Microservices:-
=============
Microservices allow a large application to be separated into smaller independent parts, with each part having its own realm of responsibility. 
-> simply, splitting one large application into many services.

Advantages:-
----------
1. Improve fault isolation: if one service encounters a fault or failure, we no need to change and deploy the entire system.
2. It will improve the team productivity
3. Deployment time is less compare to Monolithic.
4. Loosely coupled

Disadvantages:-
-------------
1. Developers may have to write extra code to ensure smooth communication between modules.
2. Coordinating deployments and managing version control across multiple services can be complex
3. Testing microservices involves complex scenarios, mainly when conducting integration testing across various services.
